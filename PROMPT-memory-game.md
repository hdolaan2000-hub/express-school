# Промпт для Claude в VS Code

---

Сверстай экран мини-игры «Мемори» по макету. Figma MCP подключён — бери данные из него, не угадывай.

## Макет

- Экран: https://www.figma.com/design/rbOutY6P00pswSk3YrEbyZ/?node-id=145-1828
- Компонент карточки: https://www.figma.com/design/rbOutY6P00pswSk3YrEbyZ/?node-id=145-2303

У карточки три состояния: **дефолтная**, **выбранная**, **угаданная**. Сними через MCP `get_design_context` / `get_variable_defs` точные размеры, радиусы, цвета, тени и типографику для каждого состояния, ассеты выгрузи через `download_assets` в `public/assets/`. Сетку поля (сколько карточек, гэпы, отступы) бери из фрейма 145-1828, не выдумывай.

Требование: **сверстать в точности по макету**, отклонения замерять попиксельно против эталонного экспорта.

## Что уже есть в репозитории

- Проект: React 19 + Vite + TypeScript, CSS Modules, без UI-библиотек. Соблюдай этот стек.
- Сцена — 1440px с абсолютным позиционированием, масштабируется через `useStageScale`. См. `README.md`, раздел «Как устроена вёрстка».
- Роутинг — по хэшу в `src/App.tsx`: тип `Tab` в `src/components/Sidebar/Sidebar.tsx`, объекты `SCREENS`, `HASH`, `TABS`, карта `MENU_FOR`.
- **Звук переворота уже лежит в `public/assets/card-flip.mp3`** — вырезан из видео-референса дизайнера. Заново не генерируй.

## Куда встроить

Новый экран `src/screens/MemoryGameScreen.tsx` + `MemoryGameScreen.module.css`, по образцу существующих (`QuizScreen`, `LessonEntryScreen`). Заведи таб `game`:

- добавь `'game'` в тип `Tab`;
- в `MENU_FOR` — `game: null` (в боковом меню пункта нет);
- в `SCREENS`, `HASH` (`game: 'game'`) и `TABS` в `App.tsx`;
- плитка «Мини-игра» на главной (`src/screens/HomeScreen.tsx`, `StatTile`) должна вести на этот экран — прокинь колбэк как сделано для «Друзей» (`onOpenFriends`).

Экспортируй константу высоты `GAME_HEIGHT` — как остальные экраны.

## Логика игры

Тайм-киллер, ничего лишнего:

1. **Старт**: все карточки показываются лицом вверх, затем переворачиваются рубашкой вверх. Дай время на запоминание (~2–3 с), переворот обратно — каскадом, с небольшой задержкой между карточками (stagger ~30–40 мс), чтобы это читалось как волна, а не одномоментный щелчок.
2. Клик открывает карточку → состояние «выбранная».
3. Две совпавшие → состояние «угаданная», остаются открытыми.
4. Две несовпавшие → через ~700–800 мс закрываются обратно.
5. Блокируй клики во время анимации переворота и во время сравнения пары, чтобы нельзя было открыть третью карточку.
6. Счётчики (ходы / очки) — только если они есть в макете, ровно как там.

**Сохранение рекордов и уровни делать не надо** — прямое указание дизайнера.

## Анимация переворота

Дизайнер прислал видео-референс. Я разобрал его покадрово, вот замеры:

- Переворот **вправо** — `rotateY`, лицевая и рубашка на одном элементе через `backface-visibility: hidden`, контейнеру `perspective` (порядка 800–1000px).
- Длительность **~220 мс**. На 30 fps карточка уходит в ребро за ~4 кадра и раскрывается полностью за ~7.
- Easing — плавный вход-выход (`cubic-bezier(0.4, 0, 0.2, 1)` или близко), без пружины.
- В середине переворота карточка чуть уменьшается — эффект перспективы, отдельным `scale` дожимать не нужно, `perspective` даёт это сам.
- Звук `card-flip.mp3` играет **в начале** переворота, на каждую карточку. Держи один `Audio`-объект на инстанс либо клонируй ноду через `.cloneNode()`, чтобы одновременные перевороты не глушили друг друга. Первое воспроизведение — только после пользовательского клика (иначе браузер заблокирует автоплей); стартовый каскад в начале игры звучать не должен либо должен запускаться после первого взаимодействия.
- Уважай `prefers-reduced-motion`: при `reduce` — мгновенная смена без вращения.

Прогони `npm run build` (`tsc -b` в цепочке — типы должны быть чистые), подними `npm run dev`, сними скриншот экрана и сравни с эталонным экспортом из Figma. Эталон положи в `reference/`, как сделано для остальных экранов. Расхождения, которые не устраняются средствами CSS, опиши в `README.md` — там уже есть раздел «Точность» с таким форматом.
